# Product 2.2 on iOS — status and handoff

Branch `feat/product-2.2-2.3-ios-20260730-223307`, based on
`6a0e7f558f8338b4ad161defa4e798041aa7c985`.

Every user-facing Product 2.2 surface is built: Today in Home, the magazine
reader, canonical catalog search and detail, AI Quick Add, Playlog, Play
Compass, Game DNA and Monthly Replay. All 25 required test areas are covered.

Two user scenarios remain blocked by the server contract rather than by the
app — see "Blocked on a server contract change" below. Nothing was faked to
work around them.

## What is done

### Contract
`Packages/GamePediaProduct22API` isolates the server contract. The OpenAPI
document is a byte-exact copy of GamePediaCoreServer
`a42ef7d0510c39811844293cc4dbebbf55a5da39`; generator 1.11.1, runtime 1.12.0
and urlsession 1.3.0 are pinned with `exact:`. Generated sources are produced
by the build plugin and are **not** committed, so checked-in Swift cannot drift
from the contract. See `PROVENANCE.md` in that package and
`scripts/verify-product22-contract.sh`.

### Data layer — all 21 user-facing operations
`GamePedia/Data/Product22`. The five EDITOR/ADMIN editorial endpoints are
deliberately not built.

* `Product22APIService` wraps the generated operations against
  `AppConfig.coreBaseURL`.
* Authorization is per call via a task local: reads use the current session,
  gesture-started mutations bind a gesture-time account expectation atomically
  through the existing `SessionCredentialAuthority`, and a guest-started
  mutation fails closed. No second refresh loop, no automatic re-send of a
  mutation, and 401 is handed to the existing session lifecycle.
* `ProductConfigStore` caches for a 5-minute account-independent TTL and fails
  closed when the flag state is degraded or unknown.
* `ProductEventRecorder` can only express contract-declared event codes, and
  its property bag has no free-text case at all.

### Domain and repositories
`GamePedia/Domain/Product22`, `GamePedia/Data/Product22/Repository`. Entities
for every feature area, explicit mappers, and repositories including the
account-isolated Today cache with stale-response suppression.

### Presentation
* Today in Home, above the legacy discovery sections, keyed by section identity
  so the server decides the count and order.
* `ArticleMarkdownRenderer` and `ArticleReaderViewController` — no web view,
  raw HTML stays literal, inline images are removed before parsing, only
  `https` sources are tappable and they open in `SFSafariViewController`.
* `Product22ListViewController` — one scaffold carrying loading / empty /
  disabled / failed / loaded, pull-to-refresh, load cancellation and
  stale-response suppression, shared by every detail screen.
* Catalog search and detail, Quick Add, Playlog list/calendar/form, Play
  Compass, Game DNA and Monthly Replay on top of it.
* `Product22SceneFactory` — Home, Search and Library route through one factory,
  so the three coordinators cannot drift.
* `L10nProduct22.swift` — 153 keys in ko/en/ja/zh-Hans, generated by
  `scripts/generate-product22-l10n.py`, which escapes Swift keywords and fails
  if the four languages disagree on the key set.

### Tests
118 new: 103 in `GamePediaTests/Product22` plus 15 in the package. 622 unit
tests pass in total against a 519-test baseline, 0 failures, 0 skipped, 0 new
warnings. All 25 required areas are covered.

## Blocked on a server contract change

Two scenarios cannot be completed in the app, and were **not** worked around
with an invented DTO. Full detail in `docs/product-2.2-contract-gaps.md`.

| Operation | What is blocked |
| --- | --- |
| `confirmCatalogSubmission` | The created or linked `catalogGameId` is inside an untyped `SuccessEnvelope`, so Quick Add cannot navigate to "the game you just registered". The confirmation screen reports only what it can derive — PRIVATE versus PENDING_REVIEW, created versus linked — and offers a catalog search instead. |
| `getCatalogSubmission` | A submission-status screen cannot be built: status, resolution and the resulting game all sit in the untyped `data`. The operation stays on the API service and no UI calls it. |

Both need the response `data` named in the contract, in the same style
`getCatalogGame` and `listPlaySessions` already use.

## Smaller follow-ups

* **Pagination.** Catalog search and the Playlog list each fetch one page at the
  contract maximum, because the cursor lives in an untyped `meta`.
* **Calendar.** The Playlog month grid is derived from typed sessions by
  `PlayCalendarDeriver` rather than fetched, because `getPlayCalendar`'s body is
  untyped. Monthly Replay is unaffected — its window, monthKey and timezone come
  from the server and are rendered verbatim.
* **Playlog note persistence.** Notes are held in memory only. If a draft is
  ever persisted across launches it needs the same encryption, file protection
  and account-deletion cleanup as the existing protected stores; otherwise keep
  note-bearing mutations online-only.

## Things worth knowing before you continue

* **Dates.** The server serialises with JavaScript `toISOString()`, which always
  emits milliseconds; the runtime's stock `.iso8601` transcoder rejects those.
  `Product22ClientFactory.configuration` installs `RFC3339DateTranscoder`, which
  reads both forms. Do not build a client without it.
* **Contract gaps.** Ten operations declare an untyped `SuccessEnvelope` body,
  both list endpoints hide their cursor in an untyped `meta`, and
  `PublicArticle` leaves `heroImage`/`relatedGames` untyped even though
  `ArticleSummary` `$ref`s them properly. Nothing is guessed anywhere; read
  `docs/product-2.2-contract-gaps.md` before adding a field. Two user
  scenarios are genuinely blocked there and need a server-side contract change.
* **SwiftGen.** `SwiftGen/swiftgen.yml` does not run against SwiftGen 6.6.3 and
  its output shape does not match the committed `L10n.swift`. The reasoning is
  in the header of `scripts/generate-product22-l10n.py`. Do not "fix" it by
  regenerating `L10n.swift` — that rewrites ~500 call sites.
* **Linking.** The app links `OpenAPIRuntime` because generated types inline
  runtime symbols into their caller. It does not *import* it: every untyped
  contract position goes through `Product22JSON` in the package, so transport
  types stay in one module. `scripts/add-product22-package.rb` is idempotent
  and re-runnable if the pbxproj wiring is lost in a merge.

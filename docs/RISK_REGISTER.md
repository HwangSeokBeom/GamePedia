## Scale

- Severity uses `Blocker`, `High`, `Medium`, `Low` for review findings.
- Likelihood is High/Medium/Low based on repository evidence, not production statistics.
- Disposition uses the required modernization classes: Keep, Improve, Replace, Remove, Add, Unresolved.

## Current top risks

Before claiming an iOS build baseline, close the remaining R-28 execution gap. Before any backend mutation, resolve R-35 without disturbing user work. Before Android scaffolding, close or formally accept R-01 through R-07, R-22, R-34, and R-36. Before beta, close R-09, R-14, R-16, R-20, R-22, R-23, R-26, and R-37. R-24 requires a separate owner-authorized cleanup because the files are user-owned and may contain unreconciled work.

## Review cadence

Review at every roadmap phase exit, after any auth/schema/deployment/push/deep-link change, and during 24-hour/7-day/30-day release reviews. Each closed risk must cite the actual verification artifact; plans and generated configs are not execution evidence.
